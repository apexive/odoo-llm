What Is LLM MCP Client?

A bridge between Odoo's AI assistants and the wider MCP ecosystem

MCP (Model Context Protocol) is an open standard that lets AI assistants call tools from any compatible server. This module makes Odoo a MCP client: it pulls tool definitions from remote MCP servers, registers them as llm.tool records, and proxies tool calls to the remote server when an AI assistant decides to use them. All of this happens transparently inside a normal Odoo AI conversation.

Key Features

Everything you need to consume external MCP tools from Odoo

Automatic Tool Sync

Click Sync Tools and the module calls tools/list on the remote server, creating or updating llm.tool records automatically. Removed tools are deactivated, not deleted.

Bearer Token Auth

Supports both anonymous and Bearer token authenticated MCP servers. Tokens are stored securely per server record and sent as Authorization headers.

Test Connection

One-click connectivity test sends initialize and ping to the server and shows a clear success or failure notification.

Mixed Tool Threads

Local @llm_tool decorated tools and remote mcp_client tools can coexist on the same assistant. The AI picks whichever is appropriate for each task.

Schema Preservation

The full JSON input schema from the remote server is stored and forwarded to the LLM unchanged, ensuring the AI sends exactly the right parameters to each tool.

Sync Status Tracking

Each server record shows its last sync timestamp, success/error status, and tool count. Errors are stored in the record for easy debugging, not just logged.

Up and Running in 3 Steps

No code, no configuration files, no extra services to deploy

1

Add an MCP Server

Go to LLM → Configuration → MCP Servers (Client). Enter the server URL and optional Bearer token.

2

Sync Tools

Click Sync Tools. The module imports all tools from the remote server as llm.tool records.

3

Assign to Assistant

Add the synced tools to any llm.assistant or llm.thread just like any other tool. The AI will call them automatically.

Technical Details

Clean architecture that hooks into existing llm_tool extension points

Non-Invasive Extension

Uses the existing _get_available_implementations() hook in llm.tool to register the new mcp_client implementation type. Zero changes to any upstream model.

def _get_available_implementations(self):
    impls = super()._get_available_implementations()
    return impls + [
        ("mcp_client", "External MCP Server")
    ]

Automatic Dispatch

The {implementation}_execute naming convention means mcp_client_execute() is picked up automatically by the tool dispatch chain. No overrides to core models needed.

def mcp_client_execute(self, **kwargs):
    return self.mcp_server_id.call_tool(
        self.mcp_tool_name,
        kwargs
    )

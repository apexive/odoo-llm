What Is LLM Skills?

Persistent, versioned knowledge that travels with your code

LLM Skills turns markdown files in your addon's skills/ directory into a RAG-powered long-term memory for your AI assistants. Skills encode how to work with your specific Odoo — domain patterns, API quirks, business rules, Odoo model conventions — so the AI retrieves the right knowledge before acting, rather than guessing from base training.

Why This Matters

Without Skills

The AI hallucinates field names, writes wrong domains, misses SYSCOHADA accounting rules, and fails on Odoo-specific patterns it was never trained on.

With Skills

The AI retrieves the exact pattern for the task at hand — correct model, correct domain, correct API — before writing a single line of code or calling a single tool.

Versioned in Git

Skills live next to the code they describe. Update the code, update the skill, commit both. AI knowledge and module code stay in sync automatically.

Key Features

Everything you need to build a reliable AI knowledge system for Odoo

Zero-Touch Install

Set OPENAI_API_KEY in .env and install. The module auto-creates the OpenAI provider, fetches all models, creates the pgvector store, and bootstraps your first skill collection. Zero manual steps.

Auto-Discovery

Drop a skills/ folder in any installed addon and it's picked up automatically. No registration required, no module dependency on llm_skills needed.

Atomic Chunking

Each skill is embedded as a single unit (2000-token ceiling, zero overlap). Skills are atomic — splitting one mid-context destroys coherence. The AI always retrieves complete, actionable patterns.

SHA-256 Incremental Sync

On each boot or upgrade, only changed files are re-embedded. Unchanged skills are skipped entirely. Large skill libraries sync in seconds, not minutes.

MCP-Exposed Retriever

The technical_skill_retriever tool is automatically available to every MCP client connected to your Odoo — Claude Desktop, Claude Code, Cursor, and more.

Multi-Collection

Organize skills into domain collections — Odoo Technical Skills for generic patterns, WhatsApp Skills for messaging patterns, and so on. Each assistant retrieves from the right collection.

Skills Are Just Markdown

YAML frontmatter for metadata, markdown for content. No special tooling required.

Example Skill File 

---
id: find-overdue-invoices
title: Find Overdue Customer Invoices
tags: [invoicing, accounting, partners]
odoo_models: [account.move, res.partner]
tools: [odoo_record_retriever]
---

## When to use
When asked about unpaid or overdue customer invoices.

## Solution
Query `account.move` with domain:
`[('move_type','=','out_invoice'),
  ('payment_state','not in',['paid','reversed']),
  ('invoice_date_due','<', fields.Date.today())]`

Key fields: `name`, `partner_id`,
            `amount_residual`, `invoice_date_due`.

## Notes
Sort by `invoice_date_due asc` to surface oldest first.

Anatomy of a Good Skill

Stable ID

Kebab-case, matches filename stem. Never change after creation — it's the content hash anchor.

When to Use

One clear trigger sentence. This is what the vector search matches against the AI's query.

Solution

Concrete, copy-pasteable code. Model names, domains, field names — exactly as they are in your Odoo.

One Skill = One Question

Small, focused skills retrieve better than large, multi-topic ones. Split by business question, not by file size.

What You Can Ask

"Before querying overdue invoices, get the relevant Odoo skill."

The retriever finds the exact model, domain, and field names for your version of Odoo.

"What's the correct way to send a WhatsApp message through Odoo?"

Retrieves the WhatsApp skill with the exact method, record format, and queue_job pattern.

"How do I book a SYSCOHADA journal entry for asset depreciation?"

Domain-specific skills surface accounting rules that aren't in any LLM's base training.

"Retrieve the skill on Odoo 18 form view chatter syntax before writing XML."

Prevents the classic Odoo 18 bug: returns <chatter /> not the broken verbose syntax.
